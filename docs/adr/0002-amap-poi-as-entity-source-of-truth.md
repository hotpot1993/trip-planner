# 以高德 POI 作为攻略知识的唯一实体真源

## 背景与决策

网友笔下的景点名与地图实体之间存在系统性的不一致：「故宫」「紫禁城」「故宫博物院」指同一个地方；「古镇」「古城」在不同城市各有一个。攻略提纯的产出如果不能落到一个确定的实体上，避坑指南就只是一段无法上图、无法排程、无法与行程关联的文本，整个知识库的价值归零。

决策：**高德 POI 是整个系统的唯一实体真源**，所有攻略结论必须持有 POI 标识才能进入攻略知识库。提纯阶段只产出自然语言景点名候选加上下文线索（所在城市、行政区、同行景点）；对齐阶段用高德搜索并借助坐标与地址消歧；对不上的进入待对齐队列由人工处置。

明确否决的做法：让 LLM 直接输出 POI 标识（标识是长字符串，模型只能编造，必然大面积幻觉）；名称搜索取第一个结果（同名景点会静默错配，错了比没有更糟）。

## 后果

- 覆盖率低于正确率是被接受的代价。知识库会遇到「网友很推荐但高德搜不到」的地方，这类内容留在待对齐队列，不进入候选池。
- 待对齐队列的沉淀结果是对齐算法的训练信号，因此这个队列必须有界面，不能只在日志里。
- 实体真源被替换（例如改用另一家地图服务商）是一次全局迁移，不是局部替换。
- 坐标、地址、开放时间等硬事实全部随 POI 一起从高德获取，天然与字段级分层采信相容。
