# 拷贝 FloatTrip 代码但隔离在 third_party 目录

## 背景与决策

本项目的多 Agent 排程流水线（规划与复审循环、开放时间专项校验、候选池封闭世界的硬性检查）借鉴自 FloatTrip，而该仓库可以直接使用的模块与我们要避免的包袱混在一起。

关键事实：**FloatTrip 及其所有 fork 都没有 LICENSE 文件**，README 里写的 MIT 不生效——法律上默认「保留所有权利」。同时该仓库把一个 5.4MB 的二进制检查点库和一份 `debug.keystore` 调试签名密钥提交进了版本控制（`.gitignore` 明明列了它们，忽略规则失效），另有约 75 张 PNG、移动端工程与营销页面。

决策：需要的模块拷进 `third_party/floattrip/` 这一明确边界内，在目录下记录出处（源仓库、提交哈希、拷贝日期、改动摘要）；同时明确不搬入任何二进制状态库、密钥、移动端工程、图片与营销页面。一旦本项目需要开源或分享，替换或重写该目录即可。

## 后果

- 拷贝代码不得散布进业务层，业务层只能通过一层薄适配调用它。这条纪律比拷贝本身更重要——它把一次不可逆的污染变成一次可逆的替换。
- 该目录内的代码不享受本项目的编码规范豁免，但也不承担对外承诺；它被视为可丢弃的。
- 若将来向上游取得授权或上游补上许可证，本决定应重新评估。
- 本项目自身的原创代码必须与 `third_party/` 划清界限，否则未来无法判断哪些部分可以按自己的许可发布。
