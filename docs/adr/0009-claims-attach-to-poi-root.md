# 攻略结论挂在 POI 本体，子点通过证据引文保留

## 背景与决策

「东华门只能出不能进」这条结论的主体被抽成了独立的「东华门」，而它其实是故宫的一个门。这类提及必须能对齐到确定的实体，否则会生成一个只有一条结论、无法参与路线排序的孤立 POI——它没有足够的结论支撑它在候选池里被选中，也没有自己的开放时间与门票，排程环节拿它没有任何可用的东西。问题是「东华门」与「故宫博物院」在高德返回里看起来同样是地点，光看名称分不出谁是谁的一部分。

高德 `/v3/place/text` 的返回里有一个 `parent` 字段，它正好能把「景点本体」与「本体内部的一个点」从字段上分开。

实测（`scripts/probe_m3_poi_parent.py`）：

| POI | id | parent |
|---|---|---|
| 故宫博物院 | B000A8UIN8 | （空） |
| 故宫博物院-午门 | B000A84GDN | B000A8UIN8 |
| 故宫博物院检票处 | B0FFKL520U | B000A8UIN8 |
| 陕西历史博物馆 | B001D03PEX | （空） |
| 陕西历史博物馆停车场 | B0FFHSIN65 | B001D03PEX |
| 陕西历史博物馆游客服务中心 | B0FFH32OTD | B001D03PEX |
| 秦始皇兵马俑博物馆第1停车场 | B001D0095C | B0FFGXMLTU（不是顶层） |

决策：**`parent` 为空的是本体，非空的是子点；攻略结论一律挂在 POI 本体上，不挂在子点上。**

不需要靠名称里有没有 `-` 这种脆弱启发式——实测里 `故宫博物院检票处`、`陕西历史博物馆游客服务中心` 名称里都没有 `-`，但它们都是子点。

层级可以有不止一层。`秦始皇兵马俑博物馆第1停车场` 的 `parent` 是 `B0FFGXMLTU`（秦始皇兵马俑博物馆），而 `B0FFGXMLTU` 的 `parent` 才是 `B001D09OYW`（秦始皇帝陵博物院）。所以归并不是「看 `parent` 是否为空」一步，而是**沿着 `parent` 链一直走到根**，根才是本体。

理由是行程的形状：行程里的一天项就是「故宫博物院」，而不是「午门」。挂到午门上就是挂到子点上，会生成一个只有一条结论、无法参与路线排序的孤立 POI。

这条规则同时决定了对齐阶段的搜索口径：

- 搜「故宫」时，`故宫博物院` 是答案，**带 `parent` 的一律不进候选**。实测搜「故宫」返回 10 条，其中 9 条带 `parent`，只有 `故宫博物院` 与 `北京故宫博物院北院区(建设中)` 的 `parent` 为空。
- 搜「午门」时，返回的正是子点 `故宫博物院-午门`，这是正确答案，但它 `parent` 指向 `B000A8UIN8`。对齐要把结果**沿 `parent` 链归并到本体**，落到 `故宫博物院` 上。
- 原文里说的「午门」「神武门」不丢失，通过证据引文保留——`claim_evidence` 里存着那段原文片段，用户在结论详情里看得到原话，只是这条结论的主体是故宫博物院。

## 后果

- `poi` 表需要记住 `parent_poi_id`。这个字段是本决定能不能落地的前提：没有它，子点与本体在库里的关系就断了，每次对齐都要重新问一次高德。它同时是 M3 需要自有 POI 适配器的原因之一——引擎的 `poi_to_spot()` 只保留规划要用的字段，`parent` 在到达 `final_plan` 之前就被丢掉了。
- 对齐结果要**显式记录两个字段**：「提及名」（网友原文里写的那个名字，如「午门」）与「归并到的本体」（`poi_id`，如 `B000A8UIN8`）。只留后者会丢掉「网友到底说的是哪个点」这个信息，`alignment_task` 的人工处置与金标准集标注都需要前者。
- 子点在本体之外**仍然入库**。它们在候选池里不是景点，但在同城相邻点移动方案、导航深链与「午门进、神武门出」这类结论的落地位置上有用。
- 归并沿链走到根，因此一个 POI 的 `parent_poi_id` 写的是**直接父级**而不是根。写根会丢掉中间层级，而中间层级正是判断类型与分区归属的线索。
- 归并不上的情形必须允许存在。`parent` 为空只说明这个 POI 不是别人的一部分，不说明它值得去：名称是通用地标或行政区/街区的 POI（搜「洒金桥」「金鱼胡同」首位返回的道路名与桥名）`parent` 同样为空，它们仍要经过名称 + 城市 + 类型的判据（docs/DESIGN.md 4.4），不能因为 `parent` 为空就自动当作可挂结论的本体。
