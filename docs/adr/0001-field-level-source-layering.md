# 字段级分层采信：官方接口管硬事实，攻略素材管软经验

## 背景与决策

「多源交叉验证」是攻略可信度的基础机制，但它单独使用时会系统性失效：如果恰逢淡季免费政策，三位网友都写「故宫现在免费」，交叉验证会给出一个高置信度的错误结论——UGC 交叉验证无法抵抗系统性过时。同一个失效模式在门票价格、开放时间、末班车时间上反复出现。

因此我们把字段按来源分域，而不是按来源投票：

- **硬事实**（坐标、地址、开放时间、门票、天气）只能来自官方数据接口。攻略素材对这类字段可以标注差异，但不得覆盖。
- **软经验**（排队时长、人少时段、最佳入口、打卡点、避坑）只能来自攻略素材——官方接口没有这类信息——由多源交叉验证定级。

两类字段在数据模型上物理隔离，互不写入。这与 FloatTrip 的「所有景点必须来自高德 API 搜索结果，LLM 不得凭空生成景点名」以及 Voyago 的「攻略仅作灵感，价格地址以后续 API 为准」是同一原则的两种表述。

## 后果

- 攻略提纯的产出一开始就不是「事实」，而是「待验证的经验」，去噪机制因此变得简单且便宜——不需要再用一个 LLM 去甄别另一个 LLM。
- 界面必须能同时呈现同一景点的硬事实与软经验，且明确区分来源，否则用户无法判断该信哪一个。
- 若将来引入新的数据源，必须先在硬事实/软经验两类中站位，不允许出现只属于它自己的第三类字段。
