# 坐标统一以 GCJ-02 存储

## 背景与决策

这是一个隐蔽但一定会咬人的问题：唯一实体真源（高德）返回的是 GCJ-02 坐标，而通用地图库（Leaflet 配 OSM 瓦片）吃的是 WGS-84。两者混用而不做转换，景点会偏移约五百米——图上看不出错，但导航会把人导到隔壁街道。

决策：**全库统一以 GCJ-02 存储坐标，并把坐标系写进字段名**（如 `lat_gcj02`），让「这是哪个坐标系」在代码里无处可隐。

选择 GCJ-02 而不是更「标准」的 WGS-84，理由是转换次数与出错机会：唯一真源与应用内地图同为 GCJ-02，热路径上零转换；只有路书导出这一条边需要转换。若存 WGS-84，则入库与应用内渲染两处都要转换，而转换本身是近似的（米级误差），忘转一次就是五百米。

## 后果

- 任何新增的硬事实来源在写入坐标前必须显式声明其坐标系并转换，不允许直接落库。
- 导出路书若需要通用地图库，必须在导出时用一次 GCJ-02 转 WGS-84；本决定与「导出路书不包含地图」共同生效后，这条转换边目前不存在。
- 字段名带坐标系后缀是一项纪律，不是风格偏好：未来任何人看到裸 `lat` 都应该认为这是缺陷。
