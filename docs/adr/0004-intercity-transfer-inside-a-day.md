# 城际转移归入当天且不占用天数

## 背景与决策

多城市行程里，两个相邻城市之间的移动既不属于出发城市的「玩」，也不完全属于到达城市。它是否单独占一天，会同时决定行程表的形状、总天数的算法、预算面板的归类口径与天气面板按城市分组的依据。

决策：**城际转移是当天行程里的一个组成部分，不独立占天**。总行程天数等于各城市停留天数之和。转移默认归入出发城市的最后一天，系统按实际车次时长自适应（长车程或需转机时改建议归入到达城市的第一天），用户可以拖拽覆盖。

这条规则是「用户设置各城市停留天数、系统自动计算总行程天数」这个产品表述能够成立的唯一前提——如果转移额外占天，用户设的 3 加 3 就永远不等于系统算出的天数。

## 后果

- 行程数据模型里「城市停留」必须是一等实体，因为停留天数是用户输入而非从天列表数出来的结果。
- 每一座城市停留的每一天都带着归属，因此天气、预算、导航起点的城市归属无歧义。
- 那个带着转移的日子究竟算谁的，是一个需要显式规则并按车程自适应的默认值，不是可以留空的地方。
