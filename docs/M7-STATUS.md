## 一、为什么置信度呈现不是「加个徽章」

设计第 4.5 节：

> 一条结论只有在同时满足三件事时才能进入攻略知识库：有原文证据、已对齐到 POI、
> 独立来源数已计入。置信度由独立来源数决定，多源的为高置信，单源的标为待验证个例。

「**标为**待验证个例，而不是丢弃」——这句话把「呈现」变成了必须做的事：单源经验
仍然展示，但**必须让读的人看得出它是单源**。M5 的城市页与行程页做到了这一点，
但漏掉了这份项目里最该有它的那个地方。

---

## 二、置信度呈现——**已做**

### 1. 路书原先根本不带置信度

`roadbook_render._item` 把结论一律平铺：

```html
<li class='av'>避坑 · 中山陵陵园很大，从停车场走到台阶下就要二十分钟，建议穿运动鞋。</li>
<li class='hl'>打卡 · 中山陵免费但需要预约。</li>
```

`RoadbookItem.highlights` 里只有一个字符串，来源数在装配时就丢了。于是
「三个人都这么说」与「一个人这么说」在这份**带上路**的文件上长得一模一样——
而它正是断网时唯一的依据：在路边低头看的人，没法回主项目查这句话是谁说的。
区分这两件事是整个信任模型存在的理由（Q34、ADR-0008），**最需要它的地方反而缺席**。

现在 `domain/roadbook.RoadbookClaim` 带着独立来源数，渲染成每条后面的一句：

```html
<li class='av'>避坑 · 夫子庙晚上人多，节假日基本走不动。<span class='src'>待验证的个例（只有 1 个来源）</span></li>
```

`.src` 用 `--ink3`，不跟打卡/避坑的色条抢——朱砂只留给「计划会失败」的那三类，
一个来源数是提醒，不是警报。

### 2. 那句话本身有个假话

界面里两处各写了一遍同一个三元表达式（行程页 `RouteRail.tsx`、城市页
`CityCandidates.tsx`）：

```ts
confidence === 'high'
  ? `${independent_source_count} 个独立来源`
  : '待验证的个例（只有 1 个来源）'
```

门槛是 `MIN_INDEPENDENT_SOURCES = 3`，所以**2 个来源的结论会被说成「只有 1 个
来源」**。那是在描述一个不存在的数字——而且因为它看起来只是保守，几乎不会被
注意到。（真库里那条「陕历博周一闭馆」当时正是 2 个来源，于是界面上写着
「只有 1 个来源」。它恰好是真的，纯属巧合；见第三节。）

收成 `domain.knowledge.describe_confidence` 一处，三档：

| 来源数 | 那句话 |
|---|---|
| ≥ 3 | `N 个独立来源` |
| 2 | `待验证的个例（2 个来源，未达交叉验证门槛）` |
| ≤ 1 | `待验证的个例（只有 1 个来源）` |

两个刻意的形状：

- **只收来源数，不另收一个置信度。** 级本来就是由数推出来的（`confidence_for`），
  两个入参就有传得不一致的可能，而那时界面会显示一个与数字矛盾的标签。
- **措辞在服务端出，前端只渲染。** `InsightOut` / `ClaimBriefOut` / 工作台的
  `ClaimOut` 都多一个 `confidence_text`；行程页与城市页那两段三元表达式删掉，
  命令行 `ls align show` 里自己判的「高置信 / 待验证个例」也删掉。跨语言的
  单一出处只能这么实现：Python 与 TypeScript 各写一份，就是两个可以各自跑偏
  的地方。

### 3. 真机数据现在长这样

```
ls export trip_5f8dec330aa1
《南京、西安 5 天》5 天、14 个天项、2 条预约
已写出 data\exports\trip_5f8dec330aa1.html（13 KB，零外部引用，可离线打开）
```

页面上的 21 条结论，每条后面都是「待验证的个例（只有 1 个来源）」。这是这份
数据的实情：5 篇素材、4 个独立来源、门槛 3，**没有一条结论被交叉验证过**。
不是回归，是终于说出来了。

## 三、过程中撞出来的两处，压在置信度的地基上

这两处都不在原计划里。发现它们的方式是同一个：**去看那个数字是怎么算出来的。**

### 1. 转载判重的长度粗筛漏掉了整类转载——设计列为致命的那条风险真的发生了

`ingest._find_repost` 里有一道粗筛：

```python
shorter, longer = sorted((len(existing), len(body)))
if shorter == 0 or shorter * 3 < longer:
    continue
```

理由是「长度差三倍以上时，较短的那篇被覆盖满也达不到阈值」。**这句话不成立**：
覆盖率的分母**就是较短的那一篇**（`similarity.overlap` 特意换过序，好让「长文里
摘了一段」与「把一段扩写成一篇」得到同样的判定），所以短篇被整篇照搬时覆盖率是
1.0，与两篇的长度差无关。

真库里的代价：

| | |
|---|---|
| 两篇素材 | 459 字《西安三天，博物馆和城墙》（知乎）、99 字《【转】西安博物馆预约提示》（携程） |
| 真覆盖率 | **0.722**（阈值 0.60，最长公共片段 44 字） |
| 粗筛 | `99 × 3 = 297 < 459` → 从没进过比对 |
| 后果 | 两篇都没归组；同一条「陕历博周一闭馆」算成「**2 个独立来源**」 |

设计第十一节的风险表第一行就是这件事：「独立来源去重失效 → 置信度退化成转发量，
整个信任模型是假的」。它在这份唯一真实的数据上发生了，而**全库唯一一条看起来
被交叉验证过的结论，其实是同一篇数了两遍**——那两篇里有一篇标题就叫「【转】…」。

改法与配套的三处：

1. **粗筛换成字符多重集合的交集占比。** 公共片段里的每个字符都必须同时出现在
   两篇里，所以「交集字符数 ÷ 较短篇长度」一定是真覆盖率的上界。O(n)，比
   `SequenceMatcher` 便宜，而且只会筛掉**确定**不够格的对。它故意是松的。
2. **补 `relink_reposts`：第一层原先只在导入那一刻跑。** 判据改过、或者导入时
   判错了，历史数据永远修不回来——而 ADR-0008 说得清清楚楚，归组是「可以对
   同一批素材反复执行的命令」。第二层做到了，第一层当时没有。配套加了
   `ls pipeline merge`（只重算置信度那一步），`ls group run` 现在两层都跑。
3. **`recount_independent_sources` 改成现查素材表**，不再读
   `claim_evidence.source_group_id`。那一列是**提纯那一刻**抄下来的快照，而归组
   按设计可以反复重跑；照快照算的话，ADR 要求的那个动作（「置信度一旦按文字复制
   口径算出高置信，第二层跑完之后是要被降级的」）永远不会发生。真库里 39 条证据行
   的组号**全是 NULL**，就是这么来的——只修判据、不修计数，数字一分都不会变。
4. **「数几个独立来源」原先有三份实现**（`domain/knowledge` 的属性、`save_claim`
   里的推导式、`recount` 里的 SQL），收成 `count_independent_sources` 一处。
   三份实现就是三个可以各自跑偏的地方，而它们都自称「独立来源数」。

顺带订正 `basis`：导入转载时建的组写的是 `domain_author`（同站同作者），判据明明
是 LCS 覆盖，该是 `similarity`。`schema.py` 里那句「`domain_author` 这个取值在
实现里没被用到」当时就是错的。

**修完之后的真库**：1 个来源组（`similarity`，知乎原文 + 携程的【转】），
38 条结论的来源数**全是 1**。原先那条 2 个来源的「陕历博周一闭馆」回到了 1。

### 2. 一处判断只留了一个数字，但它原先待在三个地方

见上面第 4 条。写在这里是因为它的形状值得记住：**同一个数在三处各算一遍，
不会报错，只会让三处慢慢不一致**。发现它的办法是把「这个数字是怎么来的」
从界面一路问回数据库——问到最后发现有三份答案。

## 四、下一件：同一件事被拆成好几条——**尚未做**

路书那一页现在把问题照出来了。真行程的 21 条结论里：

| 同一件事 | 几条 |
|---|---|
| 陕历博周一闭馆 | 2（「不要安排周一去」/「安排行程时要避开」） |
| 游5路（306路）会拉你去买玉 | 2 |
| 从西安北站坐 14 号线转 9 号线到兵马俑 | 2 |
| 陕历博要预约、提前 3 天、8 点放票 | 5 |

后果有两层：一是手机上同一句建议读五遍；二是**置信度被拆散了**——同一件事的
若干说法各自记着 1 个来源，谁也没到门槛，而合起来本来能看出「有两篇素材都提到
它」。

这属于设计 4.3 里那个**尚未落地**的「结论同源」第二层（第 168 行写着「第二层的
实现在 M3 尚未落地」）。判据是「同一主体 + 同一 facet + 同一极性 + 正文近似」，
`merge_claims` 现有的判据只做「抹掉空白与标点后完全相同」，够不着
（「十四号线」与「14 号线」、「要」与「需」、「提前三天」与「提前 3 天」）。

**它不塞进置信度呈现这一件里**，因为它改的是知识库而不是界面，而且 ADR-0008
明确说放宽的误差方向是把独立来源错并成一个、把高置信降级——那是另一个方向的
错误，要单独定阈值、单独验。

## 五、还没做的 M7 两件

### 边界情况

首个已确认的：`weather_service.forecast_for_city` 最后那个「两个来源都没取到」
的分支，返回的 `CityForecast.source` 是 `WeatherSource.AMAP`——预报为空，来源却
写着「高德」，界面于是显示「来源 高德」配一片空白。空预报配一个假的来源名，
正是「算不出 ≠ 0」那一类。

### 性能

首个已确认的：`candidate_pool._fill_ratings` 对每个缺评分的 POI **串行打一次
高德、无上限、无节流**，而且发生在**每一次规划请求**里（真库 100 个 POI 有 26 个
缺评分；换成新城市池子 60 条就是最坏 60 次串行请求）。它的 `except Exception`
还会把我们自己的 bug 报成「高德没给评分」。

## 六、怎么复核这一轮

```powershell
# 两层归组 + 重算置信度（幂等，可反复跑）
.venv\Scripts\ls.exe group run
.venv\Scripts\ls.exe pipeline merge

# 看某个景点上的结论与它们的来源数
.venv\Scripts\ls.exe align show B001D03PEX

# 导出真行程的路书，翻到有结论的那几天
.venv\Scripts\ls.exe export trip_5f8dec330aa1
```

真库里那份路书现在每条结论后面都跟着「待验证的个例（只有 1 个来源）」——
**这是实情**，不是显示坏了。要让某一条变成「N 个独立来源」，只能再导入几篇
真的各写各的素材。
