## 一、已完成

| 迁移 | 内容 | 为什么需要 |
|---|---|---|
| 5 | `poi.parent_poi_id`、`source_document` 三列、`extraction_run`、`llm_cache` | 认层级、判重、留提纯运行记录、避免重复付费 |

### 代码分层

```
domain/     similarity.py    LCS 覆盖（ADR-0008），含「已知盲区」的回归测试
            extraction.py    引文定位与校验——「提纯不产生新事实」的执行点
            poi.py           POI 的类型分类、层级、跨城校验
            lineage.py       本体是谁、哪些候选属于它（纯计算）
            align.py         名称 + 城市 + 类型三判据，归并到本体
            evaluation.py    命中判定（主体 + 极性 + 事实点）与三指标（ADR-0010）

adapters/   poi.py           自有高德 POI 适配器（引擎丢掉了 typecode 与 raw_json）
            poi_lineage.py   补齐候选集之外的祖先链
            extract.py       提示词、结构化输出、按内容缓存

services/   ingest.py        导入、判重、第一层归组
            knowledge_store.py  结论/证据/待对齐/提纯运行的落库
            pipeline.py      四步编排：提纯 → 对齐 → 归组 → 合并
            gold_store.py    金标准集的读写（标注必须落回原文）
            evaluation.py    取数与算账边界：预测池、分母、ADR-0009 体检

api/        workbench_routes.py  工作台的读写接口
            gold_routes.py       标注队列与评测结果
            pipeline_routes.py   导入与管线（SSE 报进度）
cli.py      ingest / extract / group / align / pipeline / eval
```

接口层把「素材落库」与「管线跑一轮」从命令行搬进了界面——
它们是「标注 30 篇」做得完的前提。

### 验收条件的现状

设计里 M3 的完成标志是「能报出抽取精确率、召回率与对齐准确率」。

| 指标 | 现状 |
|---|---|
| 抽取召回率 | **100%（13/13）**，样本 1 篇 |
| 抽取精确率 | **92.9%（13/14）**，样本 1 篇 |
| 对齐准确率 | **76.9%**（判得出来的 13 条里错 3 条，**全是「没挂上」而非「挂错」**） |
| 引文接地率 | 真实模型 49/49 精确子串命中 |
| 对齐（离线探测） | 16 条样本 14/14 命中、2/2 正确拒绝（`scripts/verify_align.py`） |

三个数字都报得出来了，**但样本只有 1 篇 13 条，远不到设计要的 30 篇**。
`ls eval run` 每次都把这个警告打出来，不因为是自用工具就省略——没有它，
「涨了两个点」到底是提纯变好了还是噪声，无从判断。

第一批数字还抓出了一个真缺陷（`太和殿` 挂在子点上）、
以及一个比它更值得记的问题：**`align_pending` 只处理 pending 的待办，
对齐算法的改进不会回流到已解析的数据上**。详见 `M3-PROBE.md` 第六节。

## 二、未完成

按对 M3 验收条件的贡献排序：

### 1. 把金标准集标到 30 篇（人在电脑前做的事）

框架、接口与三个指标都已经就位（`ls eval gold` / `ls eval run`），
**缺的是标注本身**。现在 5 篇素材里标了 1 篇，设计要的是 30 篇。

这件事没有捷径：金标准的价值恰恰来自「人独立读过原文」。
`ls eval gold` 会一直显示进度，`ls eval gold --done` 时记下有没有看过模型输出
（`model_output_seen`）——看过再标会偏乐观，这个偏差要留在数据里。

标注时两条要记住：

- **引文必须原样来自正文**，位置由程序算。引文找不到原文，这条标注就写不进去
- **`expected_poi_id` 要填本体，不是子点**（ADR-0009）。
  第一次标注就踩了：把「太和殿」填成了 `故宫博物院-太和殿`，
  评测于是去惩罚一个正确的归并

### 2. 数据工作台界面（前端）——已完成

`web/src/views/Workbench.tsx` 与 `web/src/views/workbench/`。形状是**校勘**
而不是表单：左边正文、右边批注栏，中间的媒介是「用鼠标划一句话」。
页面上的两条硬要求都落进了实现：

- **模型候选默认不显示**，藏在一个开关后面。打开时会记下「这篇标注时看过
  模型输出」（写进 `gold_set.model_output_seen`）——这是日后判断一个偏乐观的
  指标是不是标注方式造成的唯一线索。正文上是**两层标记**，权重刻意不对等：
  人工标注有底色与实线，机器候选只有一道虚线。
- `dropped_count` 不为零的篇在「提纯」页单列出来。

顺带把「导入素材」与「跑一轮管线」放进了工具栏——它们是「标注 30 篇」做得完
的前提，而这两件事原先只能在命令行做。

后台接口一览：

| 页面区块 | 接口 |
|---|---|
| 素材标注状态 | `GET /api/workbench/gold` |
| 标注材料（正文 + 模型候选 + 已有标注） | `GET /api/workbench/gold/{id}` |
| 加/删/补标注 | `POST .../labels`、`DELETE .../labels/{id}`、`PATCH .../labels/{id}` |
| 标记标完 | `POST .../{id}/done` |
| 三个指标 | `GET /api/workbench/eval` |
| 待对齐队列 | `GET /api/workbench/alignments` |
| 提纯概览 | `GET /api/workbench/extractions` |
| 库里已有的 POI（标注时选对齐目标） | `GET /api/workbench/pois` |
| 粘贴导入 | `POST /api/ingest` |
| 跑一轮管线（SSE 进度） | `POST /api/pipeline/run` |

### 3. 前端仍然没有自动化测试

这一轮加的不是测试，是**两个能问浏览器的脚本**（都靠 Node 24 自带的
WebSocket 走 CDP，不需要装 puppeteer）：

- `scripts/shot.mjs` —— 按指定宽度截图并量横向溢出。它取代了
  `chrome --screenshot`，因为后者下 `--window-size` 与真实布局视口可以不等
  （实测要 390 却渲染成 489），截出来的图**看起来**被切掉，会让人去修一个
  并不存在的移动端 bug。
- `scripts/verify_web_annotate.mjs` —— 在真实浏览器里造一个**跨标记边界**的
  选区，检查表单拿到的引文与偏移是否逐字一致。它是写这一页时唯一抓到真 bug
  的东西（见第三节最后两行）。

它们不是测试套件的一部分，但比「无头浏览器截图人工核对」强一档：
一个能量化，一个能断言。

### 4. 第二层归组的真实数据验证

`group_by_conclusions` 只在小样本上测过。真实素材库里「逐句改写」
长什么样还没见过——阈值 0.80 是按推理定的，不是实测定的。
`M3-PROBE.md` 第四节已经实测过一次：它在逐句改写面前**完全不 work**
（精确指纹交集为 0），所以这个阈值调不调都没用，需要的是别的判据。

### 5. 已解析的待办不会跟着对齐算法一起变好

金标准集第一批数字抓出来的问题：`align_pending` 只处理 `pending` 的待办，
一条待办被解析之后就再也不会被重新检查。**对齐算法的每一次改进都只对
新数据生效**，旧结论留在原来的（可能是错的）POI 上。

现在有 `ls align audit` 能查出所有挂在子点上的结论与待办（ADR-0009 体检），
但「怎么安全地把一条已落库的结论挪到另一个 POI」还没有工具——
涉及它与别的来源合并过的证据、以及独立来源计数要重算。

### 6. 复验扫描（`ls verify scan`）

设计把它放在 M7，但 `claim.verify_due_at` 已经在算了。
可以先做一个只读的清单，让人看得见哪些结论快过期。

## 三、动手过程中踩到的坑（都已修）

| 症状 | 根因 | 教训 |
|---|---|---|
| 对齐准确率只有 14% | 判断「本体还是子点」需要父节点，而父节点经常不在搜索结果里 | 外部数据的层级关系要主动补全，不能假设它在结果里 |
| 对齐 14/14 通过，结论一条也写不进去 | `claim.poi_id` 有外键，对齐成功时没把 POI 写进 `poi` 表 | **纯函数测通 ≠ 端到端跑通**，真实路径必须跑一次 |
| 排序分全都一样，差值恒为 0 | `min(score + bonus, 1.0)` 把加成夹掉了 | 排序分的上界不要夹，它只是排序用的 |
| 另一个测试报外键失败，根因在几十行外 | `with connect(db) as conn:` **退出时不提交** | 已钉成 `tests/test_store_transaction_discipline.py` |
| 工作台页面 500 | 库里存着早先版本的 JSON 形状 | 对库里的 JSON 不能盲信 |
| 城市挂载撞外键 | 高德给区县级 adcode，`city` 表存市级 | 层级不同要先归档，找不到就报错 |
| 评测报「太和殿 挂错」 | 是归并逻辑修好**之前**的旧数据；`align_pending` 不复查已解析的待办 | 修好算法不等于修好数据，要有一条针对陈旧结论的体检（`ls align audit`） |
| 测试全绿，换个解释器 36 个失败 | 项目依赖装在 `.venv` 里，全局 python 缺 `langgraph` | 跑测试要用 `.venv\Scripts\python.exe` |
| 划选跨过已标注的段落时，标注表单不出现 | 批注序号是 `<mark>` 的**子节点**，`Range.toString()` 把序号数字也算进了选区，于是选出来的字符串比原文多几个数字，偏移校验失败 | 装饰性的序号要用 CSS 伪元素（`attr(data-note)`），不进 DOM 文本。这个 bug 是 `scripts/verify_web_annotate.mjs` 抓到的 |
| 手机截图看起来右边被切掉 | `chrome --screenshot` 下 `--window-size` 与真实布局视口可以不相等（要 390 渲染成 489） | 截图要用 CDP 的 `Emulation.setDeviceMetricsOverride` 钉死视口（`scripts/shot.mjs`），否则会去修一个不存在的 bug |

## 四、下一步建议

M3 的**代码部分到这里就齐了**：链路、评测、界面、导入与管线接口全部可用，
三个指标在真实数据上跑得出来。剩下的按价值排序：

1. **把标注标到 30 篇**——唯一还缺的验收条件，只能在电脑前一篇篇做。
   界面已经就绪（`#/workbench/annotate`），进度显示在标题右边
2. **重新对齐工具**（第二节第 5 条）——已落库的结论挂错了 POI 时，
   现在只能人工删了重来。涉及与别的来源合并过的证据、以及独立来源计数重算
3. **`ls verify scan`**（第二节第 6 条）——`verify_due_at` 已经在算了，
   缺的只是一个看得见的清单
4. 之后才是 M4 预约子系统

界面这一步的判断值得回看：原先写的是「界面可以稍后，`ls` 命令已经能跑完整条
链」。这个判断只对了一半——**跑链**确实用命令行更快，但**标注 30 篇**是一件
重复几百次的手工劳动，那正是界面该省下的成本；而它一到手就抓出了一个
命令行路径上永远不会暴露的 bug（划选失效）。
