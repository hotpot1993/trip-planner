# 路书

本地优先的旅行攻略规划工具。它解决三个问题：

1. **网友攻略里的信息不可信也不可用**——把散落的自然语言变成可溯源、有置信度、能挂到具体景点上的结论
2. **需要预约的景点会让人白跑一趟**——故宫、陕西历史博物馆这类景点的预约规则必须准确且醒目
3. **一次旅行常常跨多座城市**——而大多数工具默认单城市

第一项与第二项是挂在第三项上的信息层，**多城市规划是骨架**。

### M0 已落地

- **引擎隔离**：`third_party/floattrip/` 从上游提交 `ec911f7` 拷入 48 个引擎文件（约 7,900 行），剔除 `api/`、`main.py` 与 `core/auth.py`。出处、剔除理由、两处改动摘要与 48 个文件的上游哈希记录在该目录的 `README.md` 与 `MANIFEST.txt`
- **表结构**：本项目七域共 17 张表，与引擎自带的 13 张表共存于同一个 SQLite 文件。坐标字段一律带 `_gcj02` 后缀
- **领域规则**：不含任何框架的四组规则——总天数与转移落点、规划产出与铺排、置信度与复验分级、复核门禁与预约清单
- **架构边界**：`tests/test_architecture_boundaries.py` 拦截 Web 框架渗入领域层、绕过适配层直引 vendored 代码、以及反向依赖。已实测注入违规会失败

### M1 已落地

- **行程真相在自有表**：引擎的 `plan_json` 只写不读（ADR-0007）。引擎只负责生成，落库、读取与展示全部走本项目的表
- **转换层**：`services/plan_converter.py` 把引擎产出转成自有模型，纯函数、可离线测试，承载「总天数 = 各城市停留天数之和、日期连续无洞」的不变量
- **落库与读回往返一致**：`services/trip_store.py`。未对齐的景点会带状态读回，并自动进入待对齐队列
- **可编辑**：改城市与天数后总天数与日期自动重算，日期与城市都没变的那一天保留原有内容
- **行程编辑器与路线总览图**：前端「驿道线」把城市停留与逐日事项画成一条连续的路线；实心圆点是已安排的天，空心是未安排
- **生成入口**：`POST /api/trips/plan` 已打通（引擎 → 转换 → 落库）。真实的规划需要 `AMAP_API_KEY` 与 LLM Key

**已知缺口**：前端没有自动化测试（目前靠类型检查与人工截图验证）；生成动作是同步接口，跑一次要一到几分钟且没有进度反馈，带 SSE 进度的界面属于 M1 的剩余部分。

319 项测试全绿，`ruff` 无告警。

## 快速开始

```powershell
# 1. 建立虚拟环境并安装依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

# 2. 配置环境变量（高德 Key 与 LLM Key 必填）
Copy-Item .env.example .env.local
# 然后编辑 .env.local

# 3. 启动本地服务
.\.venv\Scripts\python.exe -m lushu
# 浏览器打开 http://127.0.0.1:8756
```

> **新增了顶层包之后要重装**：`pip install -e .` 会把当时发现的顶层包写进一个
> 导入映射里。之后再新建 `lushu/xxx` 这样的顶层包，必须重跑一次 `pip install -e .`，
> 否则从项目根目录以外的地方 import 会失败——而在项目根目录里因为当前目录恰好
> 在 `sys.path` 上，问题会被掩盖。用 `ls doctor` 或从任意目录跑一次
> `python -c "import lushu"` 可以验证。

前端单独开发时：

```powershell
cd web
pnpm install
pnpm dev
```

## 目录结构

```
lushu/                    自有后端代码（接口层 → 应用服务 → 领域 → 适配器）
├── api/                  接口层，唯一允许依赖 FastAPI 的地方
├── services/             应用服务
├── domain/               领域实体与规则，不依赖任何框架
├── adapters/             外部适配器（高德、天气、12306）
├── store/                SQLite 连接与表结构
├── engine/               薄适配层，唯一允许触碰 third_party 的地方
└── cli.py                数据管线命令行

third_party/floattrip/    从 FloatTrip 隔离拷贝的引擎（见该目录 README）
web/                      前端（Vite + React + TypeScript）
tests/                    测试，含架构边界测试
docs/                     设计文档与决策记录
data/                     本地数据（不进版本库）
```

依赖方向固定为 `api → services → domain → adapters → store`，反向依赖由 `tests/test_architecture_boundaries.py` 拦截。
