# 路书

本地优先的旅行攻略规划工具。它解决三个问题：

1. **网友攻略里的信息不可信也不可用**——把散落的自然语言变成可溯源、有置信度、能挂到具体景点上的结论
2. **需要预约的景点会让人白跑一趟**——故宫、陕西历史博物馆这类景点的预约规则必须准确且醒目
3. **一次旅行常常跨多座城市**——而大多数工具默认单城市

第一项与第二项是挂在第三项上的信息层，**多城市规划是骨架**。

### M0 已落地

- **引擎隔离**：`third_party/floattrip/` 从上游提交 `ec911f7` 拷入 48 个引擎文件（约 7,900 行），剔除 `api/`、`main.py` 与 `core/auth.py`。出处、剔除理由、两处改动摘要与 48 个文件的上游哈希记录在该目录的 `README.md` 与 `MANIFEST.txt`
- **表结构**：本项目七域共 17 张表，与引擎自带的 13 张表共存于同一个 SQLite 文件。坐标字段一律带 `_gcj02` 后缀
- **领域规则**：不含任何框架的四组规则——总天数与转移落点、规划产出与铺排、置信度与复验分级、复核门禁与预约清单
- **架构边界**：`tests/test_architecture_boundaries.py` 拦截 Web 框架渗入领域层、绕过适配层直引 vendored 代码、以及反向依赖。已实测注入违规会失败

### M1 已落地

- **行程真相在自有表**：引擎的 `plan_json` 只写不读（ADR-0007）。引擎只负责生成，落库、读取与展示全部走本项目的表
- **流式生成**：`POST /api/plan/stream` 用 SSE 推送每个阶段的开始事件。前端用 fetch + 手工解析，而不是 EventSource——后者只支持 GET，且失败会自动重连，会把一次生成变成两次
- **转换层**：`services/plan_converter.py` 把引擎产出转成自有模型，纯函数、可离线测试，承载「总天数 = 各城市停留天数之和、日期连续无洞」的不变量
- **落库与读回往返一致**：`services/trip_store.py`。未对齐的景点会带状态读回，并自动进入待对齐队列
- **可编辑**：改城市与天数后总天数与日期自动重算，日期与城市都没变的那一天保留原有内容
- **行程编辑器与路线总览图**：前端「驿道线」把城市停留与逐日事项画成一条连续的路线；实心圆点是已安排的天，空心是未安排
- **错误分类**：缺配置（503 `config_missing`）、需求不全（422 `missing_input`）、城市查不到（422 `city_not_found`）、上游不可用（502）分开处置，前端各给各的下一步

### M2 已落地

- **城际转移**：落点默认出发城市最后一天，车程超过 4 小时或需转机时改落在到达城市第一天（`default_transfer_day`）
- **交通方式建议由规则给出**，不交给 LLM：距离、实际高铁耗时、有没有铁路，每一条结论都能指出依据
- **真实的 12306 接入**：车次、起终站、时刻、历时、余票状态。票价按里程估价并逐条标注「参考价」——12306 的票价接口当前不可用，余票响应里也没有价格字段
- **预算分栏**：城际交通独立成栏，参考价单独标出并整段说明「以购票时的实际价格为准」
- **多城市天气**：Open-Meteo 为主（16 天）+ 高德兜底（约 4 天），按城市分开呈现，标出来源，不宜户外的天打标记
- **转移画在它落到的那一天里面**，而不是两个城市之间的独立节点——转移是那一天的一部分

### M3 已落地

- **自有高德 POI 适配器**（`adapters/poi.py`）：引擎的 `poi_to_spot()` 丢掉了 `typecode` 与原始响应，而这两样正是分类与认层级的前提。M2 落库的 14 条 POI 里这两列全是空的
- **提纯只做搬运**：每条结论必须带原文片段，**在原文里找不到的候选一律丢弃**。真实模型跑下来 49 条候选的引文 100% 是原文的精确连续子串——这条规则在模型层面成立
- **实体对齐的判据是名称 + 城市 + 类型**：城市是硬门禁（搜「袁家村」限定西安，前五全是市区餐馆而真袁家村在咸阳）；「值得去的地方」与「只是个地名」分两类
- **结论挂在 POI 本体上**（ADR-0009）：`parent` 为空的是本体，如实测的「午门」会沿 parent 链归并到「故宫博物院」——行程里的一天项就是故宫博物院
- **独立来源按组计数**：同一篇被转载多次只算一个来源。第一层用 LCS 覆盖认转载（实测同篇 [0.051,0.852]、异篇 [0.000,0.000]）
- **置信度分级**：独立来源 ≥3 为高置信，否则标为「待验证个例」而不是丢弃——单源经验仍有参考价值，只是要让用户知道
- **数据工作台接口**：待对齐队列（带候选与**拒绝理由**）、结论与证据、提纯运行。处置接口刻意不提供「自动选最高分」的分支
- **金标准集与评测**（ADR-0010）：人工标注必须落回原文（引文要能在正文里定位，位置由程序算）；命中判定按「主体 + 极性 + 事实点位置」三关，**不按文本相似度**——「午门是唯一入口」对「只有午门能进」算命中，「门票 100」对「门票 120」不算
- **三个指标与样本量并排出现**：`ls eval run` 报召回率、精确率、对齐准确率，同时列出漏抽与多抽的原文片段。不到 30 篇时每次都打警告——一个 2 篇素材算出来的 100% 是噪声
- **ADR-0009 体检**：`ls align audit` 一条 SQL 查出所有挂在子点上的结论与待办。这条检查是金标准集第一次跑起来时逼出来的
- **导入与管线的接口**：`POST /api/ingest` 粘贴导入、`POST /api/pipeline/run` 跑一轮并用 SSE 报进度（形状与 `POST /api/plan/stream` 一致，因为管线是长任务：提纯一篇几秒、对齐一条一次高德请求）
- **数据工作台界面**（`#/workbench`）：形状是**校勘**而不是表单——左边正文、右边批注栏，中间用鼠标划一句话就得到一条待标注引文，偏移由程序从 DOM 选区反算
- **正文上是两层标记，权重刻意不对等**：人工标注有底色与实线，模型候选只有一道虚线，而且**默认不显示**。打开这个开关会记进库里（`gold_set.model_output_seen`），因为看过模型输出再标会偏乐观，这是日后判断指标是否可信的唯一线索
- **CLI**：`ls ingest paste|import|fetch`、`ls extract run|stats`、`ls group run`、`ls align run|list|show|audit|merge-pois`、`ls pipeline run`、`ls eval gold|run`

### M4 已落地

- **17 条真实预约规则**（`lushu/seed/booking_rules.json`）：官方渠道 13 条、政府或文旅公告 4 条，每条都能指到来源链接。调研说明在 `docs/M4-BOOKING-RULES.md`
- **没有一条放票时刻是零点**——按「0 点抢票」的旧攻略一定错过：湖北省博 17:18、泰山 10:00（2024 年由 0 点改的）、成都博物馆 19:00、三星堆/故宫/湖南博物院 20:00、国博/陕历博 17:00
- **入库不等于可用**：种子写进去的一律是草案，复核（`ls booking review`）才让规则对用户可见（Q10）。体检发现 error 的规则复核不过——预约规则错一个字段，用户就会白跑一趟
- **「需要预约」与「算得出放票日」是两件事**：17 条里 12 条的官方页面从不公布放票天数与时刻，界面上照实说「官方未公布放票口径」，不写「待补齐」
- **抢票与「窗口打开」分开**：有固定时刻的生成带提醒的时刻事件，只有天数的生成全天事件——写成 00:00 等于凭空造一个精度
- **行程页顶部的预约清单**，排在行程前面（时点比行程本身更紧急），按放票日倒排，带渠道、实名要求与官方电话
- **导出 `.ics`**：`GET /api/trips/{id}/booking.ics`。折行按字节算、全角标点不转义、带 Asia/Shanghai 的 VTIMEZONE——这些错了客户端不报错，只是事件不出现
- **官方名 ≠ 高德名**：种子的 `amap_name` 一栏解决它（湖南博物院 → 湖南省博物馆，苏州博物馆（本馆） → 苏州博物馆(本馆)）
- **`ls align merge-pois`**：把同一处地方的两个实体并成一个（ADR-0002 的补救）

### 关于 12306 的四个实测结论
这些都写进了 `lushu/adapters/rail.py` 的模块文档，探查脚本留在 `scripts/probe_12306*.py` 可复跑：

1. **预售期只有 14 天。** T+14 仍可查，T+15 起重定向到错误页。多城市行程常常提前几周规划，所以「查不到车次」通常是还没放票，不是出错——这一点会如实告诉用户，且**不等于没有铁路**（否则会因为一个与铁路无关的原因建议用户去坐飞机）
2. **余票响应里没有票价。** 下标 30/31/32 是余票数量
3. **票价接口当前不可用。** 所有参数变体都返回「系统忙」；经停站接口可用但不含票价
4. **站代码只用来定位城市。** 同城不同站返回的车次集合完全相同，所以按站对枚举是多余的四倍请求

席别下标用 G/D/K/T 四类车交叉验证过（26 无座、30/31/32 二等/一等/商务）。23/28/29 在普速与部分动车上出现，但无法确定确切席别名，因此只用于判断「有没有票」，不对外声称席别。

### 已知缺口与注意事项

- **M3 的验收条件达成了，但样本量没到**：三个指标能报出来，可现在是 1 篇 13 条，设计要的是 30 篇。金标准集的价值恰恰来自「人独立读过原文」，这件事没有捷径
- **对齐算法的改进不会回流到旧数据**：`align_pending` 只处理 `pending` 的待办，一条待办被解析之后就再也不会被重新检查。金标准集抓到的那条「太和殿挂在子点上」就是这么来的——把待办退回 pending 重跑一次就正确了。现在有 `ls align audit` 能查出来，但「怎么安全地把已落库的结论挪到另一个 POI」还没有工具
- **第二层归组在逐句改写面前失效**（实测负面结论）：西安原文与它的逐句改写，9 条结论与 7 条结论的精确指纹**交集为 0**——提纯的归一化把数字改写了（120→一百二、14→十四）。换成字符 2-gram 也只有 0.00。「节选转载」量得出来（0.50），「逐句改写」量不出来，而后者恰恰是第二层存在的理由。要真正解决需要标注数据，不是更聪明的字符串比较。详见 `docs/M3-PROBE.md` 第四节
- **前端没有自动化测试**，目前靠类型检查 + 两个能问浏览器的脚本核对：`scripts/shot.mjs`（按指定宽度截图并量横向溢出）与 `scripts/verify_web_annotate.mjs`（在真实浏览器里造跨标记边界的选区，检查引文与偏移逐字一致）。两者都走 CDP，不需要装 puppeteer
- **`compose_query()` 不能删**：引擎的意图节点只从 query 文本抽取日期与目的地，会把初始状态里的同名字段无条件覆盖。详见 `third_party/floattrip/README.md` 的已知适配项第 5 条
- **规划质量本身还没有评测**：M1 验证的是管道通畅，不是行程排得好不好。真实跑那次，需求里写了「看博物馆和老建筑」，排出来的第一天却是浦口乡村慢游。金标准集能解决**提纯**质量的度量，**规划**质量需要另一套同类机制
- **12306 的数据只在出发前 14 天内可用**，所以城际票价在大多数规划阶段只能给参考价。这是上游限制，不是本项目可以绕过的
- **改了顶层包结构要重装**：见下方「快速开始」里的说明

`scripts/` 下有三类脚本：`probe_*.py` 与 `probe_*.mjs` 是当初用来把外部接口或界面摸清楚的探查脚本（结论已写进代码注释，脚本留着以便接口变化时复跑），`verify_*.py` 与 `verify_*.mjs` 是对着真实网络与真实浏览器核对适配器、服务与交互的验证脚本，`shot.mjs` 是界面截图工具。它们都不属于测试套件。

1164 项测试全绿，`ruff` 无告警。跑测试请用项目自己的解释器 `.venv\Scripts\python.exe`——依赖装在 `.venv` 里，全局 python 缺 `langgraph`，直接用会有一批与代码无关的失败。

## 快速开始

```powershell
# 1. 建立虚拟环境并安装依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

# 2. 配置环境变量（高德 Key 与 LLM Key 必填）
Copy-Item .env.example .env.local
# 然后编辑 .env.local

# 3. 启动本地服务
.\.venv\Scripts\python.exe -m lushu
# 浏览器打开 http://127.0.0.1:8756
```

> **新增了顶层包之后要重装**：`pip install -e .` 会把当时发现的顶层包写进一个
> 导入映射里。之后再新建 `lushu/xxx` 这样的顶层包，必须重跑一次 `pip install -e .`，
> 否则从项目根目录以外的地方 import 会失败——而在项目根目录里因为当前目录恰好
> 在 `sys.path` 上，问题会被掩盖。用 `ls doctor` 或从任意目录跑一次
> `python -c "import lushu"` 可以验证。

前端单独开发时：

```powershell
cd web
pnpm install
pnpm dev
```

## 目录结构

```
lushu/                    自有后端代码（接口层 → 应用服务 → 领域 → 适配器）
├── api/                  接口层，唯一允许依赖 FastAPI 的地方
├── services/             应用服务
├── domain/               领域实体与规则，不依赖任何框架
├── adapters/             外部适配器（高德、天气、12306）
├── store/                SQLite 连接与表结构
├── engine/               薄适配层，唯一允许触碰 third_party 的地方
└── cli.py                数据管线命令行

third_party/floattrip/    从 FloatTrip 隔离拷贝的引擎（见该目录 README）
web/                      前端（Vite + React + TypeScript）
tests/                    测试，含架构边界测试
docs/                     设计文档与决策记录
data/                     本地数据（不进版本库）
```

依赖方向固定为 `api → services → domain → adapters → store`，反向依赖由 `tests/test_architecture_boundaries.py` 拦截。
